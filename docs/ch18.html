第 18 章

媒体：屏幕、摄像头与录制

过去，网页想用摄像头得装 Flash 之类的插件。今天，浏览器内置的 Media Capture and Streams API（WebRTC 的一部分） 只需几行代码就能打开摄像头、麦克风，甚至录制整个屏幕；配合 <video>、<canvas> 和 MediaRecorder， 拍照、录像、加滤镜都可以在浏览器里完成。

本章目标

  • 理解 MediaStream：它从哪里来（摄像头、屏幕），可以流向哪里（预览、录制、画布）
  • 用 getDisplayMedia 录屏，用 getUserMedia 打开摄像头
  • 用 <canvas> 从视频中截取照片，用 MediaRecorder 录制视频
  • 用 Media Capabilities API 检测编解码能力，给视频加滤镜
  • 修正原书示例中的几个隐蔽 bug，并养成「用完关闭摄像头」的习惯

18.5给视频加滤镜

给摄像头画面加上滤镜效果。

原书的思路：把视频流放进一个隐藏的 <video>，按一定帧率把每一帧画到 <canvas> 上，再对画布应用 CSS 滤镜。

ⓘ CSS filter 与 ctx.filter 的区别

对画布元素应用 CSS filter 只改变它在屏幕上的显示，画布里的像素并没有变，此时 toDataURL() 导出的仍是原图。 如果要导出带滤镜的照片，应该在绘制时设置 context.filter = 'hue-rotate(90deg)'（Baseline 2024）， 这样滤镜会被真正「画」进像素里。本页演示的拍照就是这样做的。

✨ 更精准的逐帧处理：requestVideoFrameCallback

requestAnimationFrame 按屏幕刷新率调用，但视频可能只有 30 帧（屏幕却是 120Hz），多画了很多重复帧。 video.requestVideoFrameCallback(cb) 只在视频真正有新帧时回调，更省资源。Baseline 2024 更复杂的实时处理（美颜、背景虚化）可以研究 WebCodecs、WebGL / WebGPU 与 Insertable Streams。

小结

  • getUserMedia（摄像头 / 麦克风）和 getDisplayMedia（屏幕）返回 MediaStream；需要 HTTPS 和用户授权。
  • 预览：video.srcObject = stream；录音录像时预览要 muted，避免回授。
  • 拍照：把当前帧 drawImage 到画布，尺寸用 videoWidth / videoHeight，导出用 toDataURL 或 toBlob。
  • 录制：MediaRecorder 的 start / stop + dataavailable；用 isTypeSupported 选择格式。
  • 能力检测：navigator.mediaCapabilities.decodingInfo() 返回 supported / smooth / powerEfficient。
  • 用完调用 track.stop() 关闭设备；逐帧处理用 rAF 或 requestVideoFrameCallback，不要写错定时器间隔。

动手练习

  1. 做一个「证件照」小工具：打开前置摄像头，画面中叠加一个人像轮廓引导框，拍照后裁剪为 3:4 并下载。
  2. 给录屏功能加上计时器（第 1 章 rAF）和「同时录制麦克风声音」选项（提示：getDisplayMedia({ audio: true }) 或把两条流的轨道合并到一个 new MediaStream([...])）。
  3. 用 start(1000) 每秒拿到一段数据块，把数据块存进数组，停止后合并成一个 Blob —— 这是上传大录像时「边录边传」的基础。
  4. 写一个函数，按 AV1 → VP9 → H.264 的顺序用 decodingInfo 找出当前设备能流畅播放的第一种编码。
