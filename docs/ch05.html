第 5 章

IndexedDB：浏览器里的数据库

localStorage 只能存字符串、容量小、查询靠遍历。当你需要离线保存成百上千条记录、按条件检索、存图片和文件时， 就该请出 IndexedDB 了。它的 API 以繁琐著称，但只要理解了「数据库 → 事务 → 对象仓库 → 请求」这条链，一切都有章可循。

本章目标

  • 理解对象仓库、键、索引、事务、请求这五个核心概念
  • 完成增、查、删的基本操作，并用版本号安全地升级数据库结构
  • 用索引和键范围（IDBKeyRange）高效查询
  • 用游标遍历、搜索和分页
  • 把回调式 API 包装成 Promise，并避开「事务自动提交」这个经典陷阱

核心概念

如果你用过 MySQL 之类的关系数据库，可以这样类比：数据库对应数据库，对象仓库（object store）对应表， 每条记录是一个 JavaScript 对象，键对应主键，索引对应索引。 不同之处在于：IndexedDB 没有 SQL，也没有固定的列 —— 同一个仓库里的对象可以长得不一样。

键：内联还是外置

内联键（in-line）：键就是对象的一个属性
外置键（out-of-line）：键单独传

事务与请求

IndexedDB 的所有读写都必须在事务里进行。事务把一组操作捆在一起：要么全部成功，要么任何一个失败就全部回滚， 这样数据不会停在「改了一半」的状态。事务分两种：readonly（只读，可以多个并行）和 readwrite（读写，同一仓库上会排队）。

5.2升级已有的数据库

应用更新了，需要给已有的数据库再加一个对象仓库。

这是 IndexedDB 最独特的设计。你的数据库活在每个用户的浏览器里：有人三个月前访问过，数据库还是第 1 版； 有人从没来过，一个都没有。你无法「统一迁移」，只能在代码里写好从任意旧版本升级到最新版本的步骤。

  • open 不传版本号时默认为 1（如果库已存在，则按现有版本打开）。
  • 版本号只能增大。用比现有版本小的数字打开会报 VersionError。
  • 重复创建已存在的仓库或索引会抛异常，所以一定要根据 oldVersion 判断。
⚠ 多标签页下的升级阻塞

用户在标签页 A 开着旧版本页面，又在标签页 B 打开了新版本，B 的升级会被 A 的连接阻塞（触发 blocked 事件）。 好习惯是在每个连接上监听 versionchange，主动关闭旧连接并提示用户刷新：

💡 索引的几个进阶选项
  • createIndex('email', 'email', { unique: true })：唯一索引，插入重复 email 会失败。
  • createIndex('tags', 'tags', { multiEntry: true })：属性是数组时，每个元素都进索引，可以按标签查询。
  • createIndex('dept_age', ['department', 'age'])：复合索引，配合 bound(['研发', 20], ['研发', 30]) 查「研发部 20–30 岁」。

5.4用游标搜索字符串

你想找出名字包含某段文字的所有员工 —— 索引只能做精确或范围匹配，做不了「包含」。

游标（cursor）像一根手指，按键的顺序一条一条指过去。每指到一条记录，就触发一次 success； 你检查完当前记录后调用 continue()，手指移到下一条；走到头时 request.result 为 null。

ⓘ 游标搜索是「全表扫描」

这种写法要把每条记录都读一遍，数据量达到几万条时会明显变慢。如果主要是前缀搜索（输入「张」找「张三」）， 用上一节的 bound('张', '张￿') 走索引会快得多。真正的全文搜索，可以考虑专门的客户端搜索库。

现代补充：事务自动提交陷阱

这是 IndexedDB 和 Promise 混用时最常见的 bug。IndexedDB 的事务没有 commit 按钮： 当事务里已经没有待完成的请求，并且控制权回到事件循环时，浏览器就会自动提交并关闭它。

ⓘ IndexedDB 能存什么

IndexedDB 用结构化克隆保存数据：普通对象、数组、Date、Map、Set、RegExp、 ArrayBuffer、Blob、File 都能原样存取；函数、DOM 节点、类实例的方法不行。 容量通常可达磁盘空间的相当比例（具体由浏览器决定），可用 navigator.storage.estimate() 查看（见第 2 章）。

小结

  • IndexedDB = 数据库 → 对象仓库 → 记录，索引是按某属性排序的目录；所有读写都在事务里，每个操作返回一个 IDBRequest。
  • 只能在 upgradeneeded 里改结构；用 if (oldVersion < N) 的阶梯式写法兼容所有旧版本。
  • 索引 + IDBKeyRange 实现精确和范围查询；「包含」式搜索只能用游标全表扫描。
  • 分页可以用 advance，但游标式分页（lowerBound(lastKey, true)）更快。
  • 用 Promise 包装或直接使用 idb 库；事务中间不要 await 与数据库无关的操作。
