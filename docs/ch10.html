第 10 章

文件操作

过去，网页想「读取本地文件」只能先上传到服务器，服务器处理完再返回结果；想「保存文件」只能让服务器生成一个下载。 今天，浏览器可以直接在本地读取用户选择的文件，生成文件供下载，在支持的浏览器里甚至可以直接写回磁盘。 文本编辑器、图片查看器、音视频播放器都可以做成纯前端应用。

本章目标

  • 用 <input type="file"> 和拖放获取 File 对象
  • 用 FileReader 以及更现代的 file.text() 读取文件内容
  • 分清 Data URL 与 Object URL，并用它们预览图片和视频
  • 用 File System Access API 写入本地文件，理解权限模型
  • 用 Blob + <a download> 实现兼容所有浏览器的导出

文件 API 全景

File 与 Blob

Blob（Binary Large Object）表示一块不可变的原始数据，可以是文本也可以是二进制。 File 继承自 Blob，额外带上了文件名和修改时间。所以凡是接受 Blob 的地方（fetch 的 body、URL.createObjectURL……）都可以直接传 File。

10.2以 Data URL 形式加载图片

让用户选择一张本地图片，在页面上显示出来。

Data URL 把数据直接编码进 URL 本身，格式是「data: + MIME 类型 + ;base64, + Base64 编码的数据」：

data:image/png;base64,UHJldGVuZCB0aGlzIGlzIGltYWdlIGRhdGE=

整个过程都在用户的浏览器里完成，没有任何数据被上传。 （如果要上传，参见第 4 章 4.4 节：把 File 放进 FormData 或直接作为 fetch 的 body。）

⚠ 别相信 accept 和 file.type

accept 只是给文件选择框的「建议」，用户可以切换到「所有文件」选别的东西；拖放更是完全不受它限制。 file.type 也只是浏览器根据扩展名猜的。前端检查是为了体验，服务器端必须重新校验文件内容。

10.3以 Object URL 形式加载视频

让用户选择一个视频文件，直接在网页里播放。

Object URL 形如 blob:https://example.com/550e8400-e29b-41d4-…，它不包含数据，只是指向浏览器内存中那个 Blob 的「门牌号」。 注意这个方法在 URL 上（原书说「文件本身有 createObjectURL 方法」是笔误）。

10.5检查和请求文件权限

使用 File System Access API 直接读写本地文件前，先检查是否有权限，没有就请求。

File System Access API 更进一步：不是给你一份文件的「拷贝」，而是给你一个句柄（handle）， 拿着它可以反复读取、甚至写回原文件 —— 这就是在线编辑器能「保存」而不是「另存为下载」的原理。 这么大的能力当然需要用户授权：

  • queryPermission 只查询不弹窗，返回 'granted'（已授权）、'denied'（已拒绝）或 'prompt'（需要询问）。
  • mode: 'readwrite' 表示请求写权限。通过文件选择框选中的文件默认只有读权限，写入前需要额外授权。
  • requestPermission 必须在用户操作（如点击）中调用。
✨ 支持现状：两套「文件系统」API
API作用支持
showOpenFilePicker / showSaveFilePicker / showDirectoryPicker读写用户磁盘上的真实文件和目录仅 Chromium
源私有文件系统（OPFS）navigator.storage.getDirectory()每个网站一个私有的、用户看不见的沙盒文件系统，速度极快，适合 SQLite 等数据库文件Baseline 2023

Firefox 和 Safari 至今没有实现用户磁盘访问的那部分，所以它必须作为渐进增强，并且始终提供 10.7 节的下载方案作为兜底。

10.6把接口数据导出为本地文件

从接口拿到 JSON 数据后，让用户把原始数据保存到本地文件。

  • 数据导出是很常见的需求，一些法规（例如欧盟的 GDPR）要求应用允许用户下载自己的数据。
  • JSON.stringify(data, null, 2)：第二个参数是第 2 章讲过的 replacer（这里不需要，传 null），第三个参数表示缩进 2 个空格，输出更易读。
  • 可写流 FileSystemWritableFileStream 除了字符串，还接受 ArrayBuffer、TypedArray、DataView 和 Blob。

小结

  • 文件只能由用户「交出」：<input type="file">、拖放，或 Chromium 的文件选择器 API。拿到的是 File（一种 Blob）。
  • 读取：现代写法 await file.text() / arrayBuffer() / bytes()；FileReader 适合需要进度事件的场合。
  • 预览：大文件用 URL.createObjectURL，用完 revokeObjectURL；Data URL 适合需要持久化的小数据。
  • 拖放：dragover 和 drop 都要 preventDefault()；用 dataTransfer.files 取文件；保留文件输入框作为无障碍兜底。
  • 写入：File System Access API 仅 Chromium 支持，需要权限；Blob + <a download> 是通用方案。

  4. 用 OPFS（navigator.storage.getDirectory()）把用户的草稿保存为私有文件，刷新后读回来。
