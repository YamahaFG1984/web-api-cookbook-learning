第 2 章

用 Web Storage 做简单持久化

刷新页面后，JavaScript 变量就全没了。想让「用户选过的主题色」「表单里填了一半的内容」在下次打开时还在， 最简单的办法是 localStorage：一个浏览器自带的、按键存字符串的小仓库。

本章目标

  • 理解 localStorage 与 sessionStorage 的区别，以及「源（origin）」的概念
  • 安全地检测存储是否可用，读写字符串数据
  • 用 JSON.stringify / parse 存对象，用 replacer / reviver 处理 Date 等复杂类型
  • 用 storage 事件在多个标签页之间同步数据
  • 列出、查询、删除数据，并了解容量上限、隐私限制等现代注意事项

Web Storage 是什么

Web Storage API 提供了一个 Storage 接口。你不需要自己创建它，浏览器已经准备好了两个全局实例：

🗃

localStorage

同一个源下所有标签页共享，关掉浏览器再打开数据依然在，直到被代码或用户清除。

📄

sessionStorage

只属于当前这个标签页，刷新页面还在，关掉标签页就没了。适合临时或敏感数据。

什么是「源」（origin）

存储空间是按源隔离的：a.com 的页面读不到 b.com 存的东西。 一个 URL 的源由三部分组成：协议 + 主机名 + 端口。路径、查询参数、锚点都不算。

和 https://example.com/a.html 比较同源吗？原因
https://example.com/b/c.html✅ 是只有路径不同
http://example.com/a.html❌ 否协议不同
https://www.example.com/a.html❌ 否主机名不同（子域名也算不同）
https://example.com:8080/a.html❌ 否端口不同

API 一览

getItem(key)
读取 key 对应的字符串；key 不存在时返回 null
setItem(key, value)
存一个字符串；key 已存在则覆盖
removeItem(key)
删除一项；key 不存在也不会报错
clear()
清空当前源的全部数据
key(index)
返回第 index 个 key 的名字
length
当前存了多少个 key

三个局限

🔤

只能存字符串

数字、布尔、对象都会被转成字符串。存对象要先转 JSON。

📦

容量小

每个源通常约 5 MB。满了再写会抛出 QuotaExceededError。

🔓

不安全

页面上任何 JS 都能读。一旦遭遇 XSS 攻击，里面的东西会被偷走。不要存密码和令牌。

⚠ 它是同步 API

localStorage.getItem 会在主线程上同步读取磁盘数据，数据量大时会拖慢页面。 所以它只适合存少量、简单的设置类数据。大量或结构化数据请用第 5 章的 IndexedDB。

本章的例子都用 localStorage，但它们同样适用于 sessionStorage，因为两者实现的是同一个 Storage 接口。

2.4持久化复杂对象

你要存的对象里有 JSON 无法直接表示的值，比如记录「最后更新时间」的 Date。

ⓘ 为什么是 04:00:00Z？

new Date(2025, 5, 2) 表示本地时间6 月 2 日零点。作者在美国东部（夏令时 UTC−4）， 换算成 UTC 就是 04:00。如果你在北京（UTC+8），输出会是 2025-06-01T16:00:00.000Z。 末尾的 Z 代表 UTC。第 11 章会详细讲时区。

序列化没问题，但 JSON.parse 回来后 lastUpdated 是个字符串，.getFullYear() 之类的方法都用不了。 解决办法是给这两个函数传「钩子」：JSON.stringify 的第二个参数叫 replacer， JSON.parse 的第二个参数叫 reviver。

直觉上可以写 if (key === 'lastUpdated') return value.getTime()，但这样行不通： Date 自带 toJSON() 方法，JSON.stringify 在调用 replacer 之前就已经把它转成了 ISO 字符串， 所以 replacer 收到的 value 是字符串，没有 getTime。 在 key === '' 那一步处理，拿到的还是原始的 Date 对象。另一个办法是用 this[key] 读取原始值。

2.5监听存储变化

同一个源在另一个标签页修改了 localStorage，你想在当前页面收到通知。

事件对象带有 key（改了哪个键）、oldValue、newValue、url（哪个页面改的）和 storageArea。 如果是 clear() 触发的，key 为 null。

ⓘ 两个容易误解的点
  • 事件只在同一个浏览器、同一台设备的其他标签页触发，不会跨设备同步。
  • 即使不监听事件，所有标签页读到的也永远是最新值。事件只是「实时提醒你数据变了」，让页面可以立刻刷新界面。
✨ 标签页之间只想「发消息」？用 BroadcastChannel

如果你并不需要持久化，只是想通知其他标签页（比如「用户已退出登录」）， BroadcastChannel 更直接：可以发送任意可结构化克隆的数据，而且不占用存储空间。Baseline 广泛可用

💡 给键加前缀

同一个源下的所有代码（包括你引入的第三方库）共享一个 localStorage。 给自己的键统一加前缀，比如 myapp:theme、myapp:draft， 列出时就能用 key.startsWith('myapp:') 过滤，清理时也不会误删别人的数据。

现代注意事项

写满了怎么办

超过配额时 setItem 会抛出 QuotaExceededError。凡是写入用户可控长度的数据，都应该包一层 try/catch：

数据并不是「永久」的

  • 用户可以随时清除站点数据，隐私/无痕模式下关闭窗口也会清空。
  • Safari 的智能防跟踪（ITP）：如果用户 7 天内没有和你的网站交互，Safari 可能删除该站点通过脚本写入的存储（包括 localStorage 和 IndexedDB）。安装到主屏幕的 Web 应用不受此限。
  • 存储分区：主流浏览器都已对第三方 iframe 的存储做了分区。嵌在 a.com 里的 widget.com iframe，和嵌在 b.com 里的同一个 iframe，拿到的是两份不同的 localStorage。

小结

  • localStorage 跨标签页、跨会话保留；sessionStorage 只在当前标签页有效。两者都按源隔离。
  • 只能存字符串：对象用 JSON.stringify / parse，Date 等复杂值用 replacer / reviver 或 toJSON。
  • storage 事件通知其他标签页数据有变化；只想发消息用 BroadcastChannel。
  • 容量约 5 MB、同步阻塞、XSS 可读 —— 只存少量非敏感数据，写入要处理 QuotaExceededError。

动手练习

  1. 做一个「草稿自动保存」：<textarea> 每次输入都存到 sessionStorage，刷新后恢复。关掉标签页再打开，观察数据是否还在。改成 localStorage 再试一次。
  2. 写一个通用的 createStore(prefix)，返回带 get / set / remove / keys / clear 方法的对象，自动处理 JSON 和前缀。
  3. 让你的 store 支持存 Date：约定序列化为 { "__type": "Date", "value": 时间戳 }，并写出对应的通用 replacer 和 reviver。
  4. 打开两个标签页，用 storage 事件实现「一边切换深色模式，另一边自动跟着切换」。
