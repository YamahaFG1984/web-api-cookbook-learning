第 14 章

设备集成

网页不只能显示内容，还能感知它所运行的设备：电量、网络、位置、剪贴板、系统分享、振动、屏幕方向…… 这些 API 的共同点是：支持程度参差不齐，并且大多涉及隐私。所以本章的每一节都会同时讲「怎么用」和「怎么安全地降级」。

本章目标

  • 读取电池状态与网络状态，并监听变化
  • 获取地理位置、持续跟踪位置，并在地图上显示
  • 用异步剪贴板 API 复制粘贴文本
  • 调用系统原生分享面板，让设备振动，读取屏幕方向
  • 理解「安全上下文」「用户激活」「权限」三道门槛，以及 Permissions API

设备 API 的三道门槛

同一个 API 在一个浏览器里能用、在另一个里不能用是常事；即使浏览器支持，设备本身也可能没有对应硬件（比如笔记本电脑不会振动）。 除此之外，为了保护用户，大多数设备 API 还设置了门槛：

API支持情况（2026）需要授权需要用户操作
电池状态 navigator.getBattery()仅 Chromium否否
网络信息 navigator.connection仅 Chromium否否
地理位置 navigator.geolocation广泛可用是否（但建议在点击后请求）
剪贴板写入 clipboard.writeText()广泛可用通常否Safari / Firefox 需要
剪贴板读取 clipboard.readText()Baseline 2024是（形式各异）是
系统分享 navigator.share()移动端普遍支持，桌面端不一否是
振动 navigator.vibrate()Android 为主，iOS 不支持否是
屏幕方向 screen.orientationBaseline 2023否否

⚠ 为什么 Firefox 和 Safari 不支持？

研究人员发现，电量百分比加上剩余时间的组合几乎是独一无二的，可以在短时间内用来跨网站追踪用户（浏览器指纹）。 Firefox 因此移除了这个 API，Safari 从未实现。所以它只能用于「锦上添花」，不能作为核心功能的依据。

14.3获取设备位置

获取设备当前的经纬度。

这是一个回调式的 API：第一个参数是成功回调，第二个是失败回调。第一次调用时浏览器会询问用户是否允许共享位置， 用户拒绝时调用失败回调。想事先知道权限状态，可以用 Permissions API：

Geolocation API 已被所有浏览器支持多年，一般不需要特性检测。除了经纬度，position.coords 里还可能有（取决于设备）： accuracy（误差半径，米）、altitude（海拔，米）、heading（方向，度）、speed（速度，米/秒）。

选项与持续跟踪

💡 包装成 Promise
ⓘ 定位（Geolocation）≠ 地理编码（Geocoding）

Geolocation API 只给出经纬度，不知道你在哪个城市、哪条街。把地址转换成经纬度叫地理编码， 反过来叫逆地理编码，这需要借助地图服务商的接口（高德、百度、Google、Mapbox、OpenStreetMap Nominatim 等），浏览器并不内置。

14.5复制与粘贴文本

给文本框加上「复制」和「粘贴」按钮：复制选中的文字；粘贴时替换选中的文字。

  • 虽然没用到 writeText 的返回值，仍然要 await 它：这样失败时（比如没有权限）才能进入 catch。
  • 文本框没有选中文字但有焦点时，内容插入到光标位置；文本框从未获得焦点时，选区位置为末尾，内容追加到最后。
  • 也可以使用 textarea.setRangeText(clipboardValue)，它会替换当前选区并保留撤销历史的行为更自然。

读取剪贴板的权限

读取剪贴板可能泄露隐私（密码、验证码……），因此需要授权。原书用 Permissions API 查询：

⚠ 各浏览器的剪贴板权限模型不同
  • Chrome / Edge：首次 readText() 时弹出权限请求；支持查询 'clipboard-read'。
  • Safari / Firefox：不支持查询 'clipboard-read'（permissions.query 会抛 TypeError）。它们在每次读取时，在光标旁弹出一个「粘贴」小按钮，用户点了才返回内容。

所以查询权限也要放进 try/catch，把「查询失败」当作「未知，直接尝试」处理。无论哪种浏览器，读取都必须由用户操作（如点击按钮）触发。

✨ 复制图片等富内容

navigator.clipboard.write() 配合 ClipboardItem 可以写入图片、HTML 等多种格式，read() 反之。Baseline 2024

14.7让设备振动

给应用加一点触觉反馈，比如操作成功时让手机轻微振动。

和自动播放视频一样，页面刚加载时不能振动，用户必须先与页面交互过。

⚠ 支持有限

iOS 上的所有浏览器都不支持 Vibration API（它们都基于 Safari 的 WebKit），部分桌面浏览器也已移除。 振动只能作为可有可无的增强，并且要克制使用 —— 频繁的振动既烦人又耗电。

14.8获取屏幕方向

判断设备当前是竖屏还是横屏。

💡 只是为了改布局？用 CSS

如果只是想在横屏时换个布局，用媒体查询 @media (orientation: landscape) { … } 即可。 需要设备的倾斜角度（做水平仪、体感游戏）时，用 deviceorientation 事件；iOS 上还需要先在点击中调用 DeviceOrientationEvent.requestPermission()。

小结

  • 设备 API 之前先过门槛：特性检测、HTTPS、用户操作、用户授权；用 navigator.permissions.query() 查询权限（但并非所有权限名都被所有浏览器支持）。
  • 电池、网络信息只有 Chromium 支持，只能用作增强；navigator.onLine 与 online/offline 事件通用。
  • 定位：getCurrentPosition / watchPosition + clearWatch；经纬度转地址需要第三方地理编码服务。
  • 剪贴板：writeText / readText 都返回 Promise，读取需要授权且各浏览器交互不同。
  • navigator.share() 调起系统分享，navigator.vibrate() 振动，screen.orientation 读取方向 —— 都要准备好降级方案。
