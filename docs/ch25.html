Canvas 2D 绘图

第 18 章用 <canvas> 从视频里截了一帧，但没有讲它本身怎么用。Canvas 是浏览器里的一块「画板」： 你用 JavaScript 下达「在这里画一条线」「把这块区域填成红色」之类的命令，浏览器把结果变成像素。 图表、游戏、图片编辑器、签名板、数据可视化……都建立在它之上。

本章目标

  • 理解 Canvas 的「立即模式」与坐标系，以及在高清屏上不模糊的正确写法
  • 绘制矩形、路径、圆弧、文字、渐变和图片
  • 用 save / restore 与变换（平移、旋转、缩放）组织复杂图形
  • 用 ImageData 逐像素处理图片
  • 写一个动画循环，并判断鼠标点中了哪个图形
  • 用 OffscreenCanvas 把绘制工作移到 Worker 中

「立即模式」是理解 Canvas 的关键：ctx.fillRect(10, 10, 50, 50) 执行完，画布上就多了一块像素，但并没有一个「矩形对象」留下来。 想把它挪个位置？只能清空画布，在新位置重新画一遍。所以 Canvas 程序通常自己维护一份「场景数据」，每次变化都根据数据重绘。

第 18 章原书的拍照代码写的是 canvas.width = canvas.width * devicePixelRatio，每拍一张画布就翻倍变大 —— 问题就出在没有区分这两个尺寸。 正确的做法永远是「从显示尺寸（或视频的真实分辨率）出发计算」，而不是在当前位图尺寸上累乘。

⚠ 忘记 beginPath 的经典 bug

不调用 beginPath()，新画的线会被加进上一条路径。于是每次 stroke() 都会把之前的所有线条再画一遍， 颜色越来越深、越来越慢，改了 strokeStyle 旧线条也跟着变色。每画一个独立的图形之前，都先 beginPath()。

25.6OffscreenCanvas：在 Worker 中绘图

你的页面既有复杂的 Canvas 动画，又有大量主线程工作（解析数据、操作 DOM），动画时不时就卡一下。

第 21 章讲过：主线程一忙，一切都会停。OffscreenCanvas 把画布的控制权转移给 Worker，绘制工作完全在后台线程进行， 即使主线程被堵住几秒钟，动画依然流畅。Baseline 2023

💡 更进一步：WebGL 与 WebGPU

Canvas 2D 由 CPU 或 GPU 绘制，但 API 本身是「一个命令画一个东西」。需要绘制几十万个粒子、做 3D 场景或图像的实时处理时， 可以在同一个 <canvas> 上改用 getContext('webgl2') 或 getContext('webgpu')，直接给 GPU 编程。 这通常借助 Three.js、PixiJS 等库完成。

小结

  • Canvas 是立即模式：画完只剩像素，程序自己维护数据，变化时清空重画。
  • 位图尺寸（width/height 属性）要等于显示尺寸 × devicePixelRatio，再 ctx.scale(dpr, dpr)。
  • 路径：beginPath → moveTo / lineTo / arc / roundRect → stroke / fill；别忘了 beginPath。
  • 用 translate / rotate / scale 变换坐标系，用 save / restore 管理状态。
  • drawImage 可裁剪和缩放；getImageData / putImageData 逐像素处理；简单滤镜用 ctx.filter。
  • 动画 = 更新 → 清空 → 绘制；点击检测靠自己计算或 isPointInPath；OffscreenCanvas 让绘制离开主线程。
