第 9 章

Web Speech API

语音已经成为继键盘、鼠标、触屏之后的又一种常用输入方式。Web Speech API 让网页可以听（语音识别）也可以说（语音合成）。 两者的浏览器支持程度差别很大：语音合成到处可用，语音识别则仍然只在部分浏览器中可用。

本章目标

  • 用 SpeechRecognition 实现听写，理解识别结果的数据结构
  • 把一次语音识别包装成 Promise
  • 用 speechSynthesis 朗读文本，选择合适的声音，调整语速和音调
  • 在切换标签页时自动暂停朗读
  • 处理中文场景（lang 设置）与浏览器兼容性

⚠ 隐私提示

Chrome 的语音识别默认会把录到的音频发送到 Google 的服务器处理，所以离线时无法使用，也可能涉及隐私合规问题。 Chrome 近年开始提供设备端（本地）识别的选项，但是否可用取决于版本、平台和语言。在处理敏感内容的应用里使用前，请评估这一点并告知用户。

识别结果的结构

result 事件的数据是「列表套列表」，第一次看会有点绕：

continuous
默认 false：识别到一句话就停止。设为 true 则持续监听，每识别一句触发一次 result，results 列表越来越长
interimResults
设为 true 时，还没说完就会收到临时结果（isFinal === false），适合实时显示「正在听写…」
maxAlternatives
每个结果最多给出几个备选，默认 1
lang
识别语言，如 'zh-CN'、'en-US'。中文用户务必设置

9.3获取可用的声音

你想知道当前浏览器有哪些可以用来朗读的声音。

每个声音（SpeechSynthesisVoice）对象有这些属性：

name
声音名称，如 "Google 普通话（中国大陆）"、"Tingting"、"Alice"
lang
语言标签，如 "zh-CN"。朗读时会按这个语言的发音规则读，中文要选中文声音，否则会读得很奇怪
localService
true 表示本地合成，false 表示需要联网的云端声音
default
是否为默认声音

页面正在朗读时，用户切到别的标签页，你希望朗读暂停，切回来再继续；离开页面时停止。

✨ 语音界面的现代玩法

把本章的两半拼起来，就是一个语音助手的雏形：captureSpeech() 听到问题 → 用 fetch 发给大模型接口 → 用 speechSynthesis 读出回答。 Web Speech API 只负责「听」和「说」，中间的「理解」可以交给任何 NLP 或大模型服务。 需要更高质量的音色时，也可以改用云端 TTS 服务生成音频，再用 <audio> 播放。

小结

  • 语音识别：window.SpeechRecognition || window.webkitSpeechRecognition，设置 lang、continuous、interimResults，在 result 事件里读 results[resultIndex][0].transcript。
  • 识别需要麦克风权限和 HTTPS，Chrome 默认使用云端服务，支持度有限，务必做特性检测。
  • 语音合成：new SpeechSynthesisUtterance(text) + speechSynthesis.speak()；可设 lang / voice / rate / pitch / volume。
  • 声音列表可能异步加载：同时调用 getVoices() 并监听 voiceschanged。
  • 朗读需要用户交互后才能开始；用 visibilitychange 暂停与恢复。
