第 1 章

异步 API

这本书里的大部分浏览器 API 都是异步的：你调用它，结果不会马上回来。 网络请求要等服务器、读文件要等磁盘、定位要等 GPS。 这一章先把「怎么等结果」这件事彻底讲清楚 —— 后面 18 章都建立在它上面。

本章目标

  • 分清三种异步模式：回调函数、事件、Promise
  • 会用 then / catch 和 async / await 处理 Promise
  • 会把多个异步任务串起来（链式）或并起来（Promise.all 家族）
  • 用 requestAnimationFrame 写出流畅的 JS 动画
  • 把一个基于事件的老 API 包装成 Promise，并了解 2024 年后的新工具 Promise.withResolvers

为什么需要「异步」

浏览器里的 JavaScript 只有一条主线程。它既要运行你的代码，也要负责响应点击、滚动、重新绘制页面。 如果「请求一个接口」要让主线程傻等 2 秒，这 2 秒里页面就是完全卡死的：按钮点不动、动画不动、连文字都选不了。

所以浏览器的做法是：把耗时的事交给后台去做，主线程继续干别的；等后台做完了，再通知你。 「通知你」的方式，就是本章要学的三种模式。

三种「通知你」的方式

📞

回调函数

你把一个函数交给 API，它做完后「回头调用」这个函数，把结果当参数传进来。最原始，也是另外两种的基础。

🔔

事件

对象会「发出」有名字的事件（click、load、error），你用 addEventListener 订阅。可以触发很多次。

🎟

Promise

函数立即返回一张「取货凭证」，将来凭它拿结果或拿错误。只结算一次。现代 API 基本都用它。

事件：EventTarget 接口

能发出事件的对象（DOM 元素、window、XMLHttpRequest、WebSocket……）都实现了 EventTarget 接口，因此都有 addEventListener 和 removeEventListener 两个方法。 事件处理函数会收到一个事件对象，里面装着「发生了什么」的细节，比如点的是哪个元素、HTTP 状态码是多少。

事件 vs Promise

事件Promise
触发次数可以很多次（每次点击都触发）只结算一次，是个一次性操作
「来晚了」怎么办在你订阅之前发生的事件就丢了任何时候调用 then 都能拿到结果
错误处理要另外监听 error 事件内建 catch，还能用 try/catch
适合什么重复发生的事：点击、滚动、消息一次性的事：一次请求、一次读取

1.1使用 Promise

你要调用一个返回 Promise 的 API，并拿到它的结果。

1.2加载图片，失败时使用备用图

你想加载一张图片，如果加载失败，就换成一张「一定存在」的备用图。

<img> 是典型的事件型 API：加载成功触发 load，失败触发 error。 我们把它包进一个 Promise，让调用方可以用更简洁的 then/catch。

判断顺序很关键：error 事件每次加载失败都会触发。如果不先检查「失败的是不是备用图」， 备用图也失败时就会进入「设置备用图 → 失败 → 再设置备用图」的死循环。

1.3链式调用 Promise

你需要按顺序调用几个异步 API，后一个要用到前一个的结果。

设想一个博客应用：getUser(id) 加载用户，getPosts(user) 加载该用户的文章。 必须先拿到 user，才能调用 getPosts。

秘密在于：then 本身也返回一个新的 Promise。 你在回调里 return 什么，新 Promise 就兑现成什么；如果 return 的本身是个 Promise，就等它完成再往下传。 于是可以一节一节地接下去，像一条流水线。

链尾的 catch 就像一个大的 try/catch：链中任何位置出错，都会跳过剩余的 then 直接来到这里。

💡 新手最常犯的错：忘了 return

如果写成 .then(user => { getPosts(user); })（花括号里没有 return）， 下一个 then 收到的会是 undefined，而且不会等 getPosts 完成。 箭头函数用花括号时，一定记得写 return。

await 会「暂停」当前这个 async 函数，直到 Promise 敲定：兑现了就返回值，拒绝了就抛出错误， 所以用普通的 try/catch 就能处理。

ⓘ 「暂停」不是真的卡住浏览器

await 暂停的只是当前这个函数。函数会把控制权交还给浏览器，浏览器照常处理点击、渲染； 等 Promise 有了结果，函数再从暂停处接着跑。这和图 1-1 里「同步傻等」完全不同。

Promise.all 有个「一票否决」的特点：任何一个失败，整体立刻失败，其他成功的结果也拿不到了。 如果你希望「成功的照用，失败的单独提示」，改用 Promise.allSettled：它永远兑现， 每个结果是一个带 status 字段的对象。

1.7把事件 API 包装成 Promise

你有一个基于事件的老 API，想把它包装成返回 Promise 的函数。

这个过程俗称 promisify（Promise 化）。套路永远是：在 new Promise 的构造函数里注册事件监听， 成功事件里调 resolve，失败事件里调 reject。

⚠ 已经返回 Promise 的 API，不要再包一层

手动 new Promise 只用于包装事件或回调型 API。像 fetch 这种本身返回 Promise 的，直接用即可。 写成 new Promise(resolve => fetch(url).then(resolve)) 是经典的「Promise 构造器反模式」—— 多写了代码，还会把错误吞掉。实际上 loadJSON 今天只要一行： fetch(url).then(r => r.json())（第 4 章详解）。

✨ Promise.withResolvers()

有时候 resolve 和 reject 需要在构造函数外面调用，以前得这样绕： let resolve; const p = new Promise(r => resolve = r);。 ES2024 加入了 Promise.withResolvers()，一次拿到三件套。Baseline 2024

现代补充：取消与超时

Promise 一旦开始就无法「撤回」。但很多场景需要取消：用户离开了页面、搜索框又输入了新字、请求太慢要放弃。 浏览器提供的标准方案是 AbortController / AbortSignal，它贯穿了整个 Web 平台： fetch、addEventListener、Web Streams、Web Locks 等都接受 signal 参数。

ⓘ 关于 Baseline 徽章

本教程用 Baseline 标注浏览器支持情况（这是 W3C WebDX 社区组推出的统一口径）： 广泛可用 表示在 Chrome、Edge、Firefox、Safari 的主流版本上都已支持超过 30 个月； Baseline 20xx 表示那一年刚在四大浏览器全部落地； 有限支持 表示还有浏览器没实现。上线前，请以 caniuse.com 和 MDN 的最新数据为准。

小结

  • 浏览器主线程只有一条，耗时操作都是异步的；通知结果的方式有回调、事件、Promise 三种。
  • Promise 只会从 pending 走向 fulfilled 或 rejected 之一，用 then / catch 或 await + try/catch 处理。
  • then 返回新的 Promise，所以能链式调用；链尾一个 catch 兜住全链错误。
  • 互不依赖的任务用 Promise.all 并行；需要逐个结果用 allSettled；还有 race 和 any。
  • requestAnimationFrame 与屏幕刷新同步；动画进度应按经过时间计算，而不是按帧数。
  • 用 new Promise 或 Promise.withResolvers() 包装事件型 API；用 AbortSignal 实现取消和超时。
