第 3 章

URL 与路由

拼接查询参数、解析相对路径、在单页应用里切换页面 —— 这些事都离不开 URL。 用字符串拼接和正则表达式处理 URL 很容易出错，浏览器早已提供了专门的工具： URL、URLSearchParams，以及更新的 URLPattern 和 Navigation API。

本章目标

  • 认识 URL 的各个组成部分，以及 URL 对象上对应的属性
  • 把相对路径解析为绝对 URL，并理解末尾斜杠带来的差异
  • 用 URLSearchParams 增、删、改、查查询参数，理解百分号编码
  • 用 history.pushState + popstate 写一个最小的前端路由
  • 用 URLPattern 匹配 URL 并提取参数，了解现代的 Navigation API

URL 的组成部分

URL 本质上是一个遵循 RFC 3986 语法的字符串。把它交给 new URL(字符串)，得到的对象会把每个部分拆成单独的属性：

属性示例值说明
protocol"https:"包含冒号，不含斜杠。也可能是 file:、ftp:、blob: 等
hostname"example.com"域名或 IP
port"8443"默认端口（https 的 443）时为空字符串
host"example.com:8443"hostname + 端口
pathname"/admin/login"以 / 开头的路径
search"?username=sysadmin"整段查询字符串，包含 ?
hash"#profile"锚点，包含 #；老式单页应用用它做路由
origin"https://example.com:8443"只读，第 2 章讲过的「源」

ⓘ 空格：+ 还是 %20？

URLSearchParams 按照 HTML 表单的规则（application/x-www-form-urlencoded）把空格编码成 +， 而 encodeURIComponent 把空格编码成 %20。两种写法服务器通常都能识别，但如果你把两者混用来手工拼字符串，就可能出问题。 结论：统一交给 URLSearchParams，不要手工拼接查询字符串。

3.5一个简单的前端路由

你在做单页应用（SPA），希望切换「页面」时 URL 跟着变，但不要真的向服务器请求新页面。

传统网站每点一个链接，浏览器都会向服务器请求一个新的 HTML 页面。单页应用则只加载一次， 之后由 JavaScript 负责「换内容」并「改地址栏」。实现这件事的两个关键工具：

history.pushState(state, '', url)

刷新页面为什么会 404？

在 /about 页面按 F5，浏览器会真的向服务器请求 /about。如果服务器上只有一个 index.html，就会返回 404。 解决办法是在服务器端配置「任何路径都返回 index.html」（通常叫 SPA fallback / history fallback）， 让前端路由接管后续渲染。

💡 各平台的 fallback 配置
  • Vite 开发服务器：默认就支持。
  • Nginx：try_files $uri $uri/ /index.html;
  • Netlify / Cloudflare Pages：_redirects 文件写 /* /index.html 200。
  • GitHub Pages：不支持重写，常见的变通是把 index.html 复制一份为 404.html，或者改用 #/about 形式的 hash 路由（hash 部分不会发给服务器）。

单页应用的好处是切换页面快、没有白屏闪烁；代价是首屏往往要预先加载更多 JavaScript，初次加载可能更慢。

✨ Navigation API：为 SPA 设计的新一代路由接口

history API 设计于 SPA 兴起之前，用起来很别扭：你得自己拦截每个链接、表单提交也要单独处理、popstate 的触发时机也很怪。 Navigation API 提供一个统一的 navigate 事件：链接点击、表单提交、后退前进、location.href = …， 所有同源导航都会经过它，你只需要决定是否「拦截」。Baseline 2026

Chrome/Edge 从 102 版起就已支持，Safari 与 Firefox 在 2025–2026 年陆续跟进。旧浏览器上请保留 history 方案作为降级， 并以 caniuse 的最新数据为准。

3.6用 URLPattern 匹配 URL

你想定义一个 URL 模式来判断 URL 是否匹配，并从中提取某一段，比如从 /api/users/123/profile 里取出用户 ID 123。

URLPattern 使用的语法和 Express、React Router 等框架里的路由语法很像：:名字 表示一个命名分组，* 表示通配符。

要提取分组的值，用 exec。匹配成功时返回一个对象，URL 的每个部分（pathname、search、hostname……）都有 input 和 groups：

更多模式语法

写法含义示例能匹配
/books/:id命名分组，匹配一段（不含 /）/books/42
/books/:id?可选分组/books、/books/42
/books/:id(\d+)用正则约束分组（写在 JS 字符串里要转义成 '\\d+'）/books/42，不匹配 /books/abc
/files/*通配符，匹配剩下的一切/files/a/b/c.txt
/:lang(en|zh)/docs只允许几个值/en/docs、/zh/docs
{ hostname: '*.example.com' }匹配 URL 的其他部分api.example.com

✨ URLPattern 的支持现状

书写作时 URLPattern 只有 Chromium 支持。2025 年 Firefox 142 和 Safari 26 相继发布支持，它已成为 Baseline 2025 新近可用的特性。需要兼容旧浏览器时，可以使用 urlpattern-polyfill。

小结

  • 用 new URL() 解析和构造 URL，别用字符串拼接和正则。它的各属性对应 URL 的各部分。
  • new URL(相对路径, 基准) 解析相对地址；基准 URL 有没有末尾斜杠，结果不一样。
  • URLSearchParams 负责查询参数：append 追加、set 替换、delete 删除、get/getAll 读取，并自动编码。
  • 前端路由 = 拦截链接点击 + pushState + 监听 popstate，服务器要配置 fallback；新项目可以考虑 Navigation API。
  • URLPattern 用 :name 和 * 描述 URL 模式，test 判断、exec 提取。
