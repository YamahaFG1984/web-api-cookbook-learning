第 16 章

把控制台用到极致

浏览器的调试器能单步执行、查看变量，功能强大。但很多时候，一句 console.log 才是最快的调试手段。 其实 console 远不止 log：它能输出带样式的文字、表格、分组、计时、计数、调用栈和断言。 本章把这些「冷门但好用」的方法一次讲清。

本章目标

  • 用 %c 给输出加样式，用日志级别区分信息、警告、错误
  • 用 bind 创建带模块前缀的日志函数
  • 用 console.table、group、time、count 组织和度量输出
  • 用 trace、assert、dir 辅助排查问题
  • 了解开发者工具中与控制台配合的实用技巧
ⓘ 本章的演示

每个演示按钮都会同时做两件事：真正调用 console（按 F12 或 Cmd+Opt+J 打开开发者工具查看）， 并在页面上的「迷你控制台」里模拟显示效果，方便你在手机上也能看到。

16.1给控制台输出加样式

你想让某条日志更醒目：更大的字号、不同的颜色。

console.log 接受任意多个参数。每出现一个 %c，就要多传一个 CSS 字符串参数，作用于它后面的文字，直到下一个 %c 为止。 样式在每个 %c 处都会重置：上例中第一段的斜体不会延续到第二段。除了 %c，还有 %s（字符串）、%d（整数）、%o（对象）等占位符。

16.3创建带名字的日志函数

应用有多个模块，你希望每条日志都带着彩色的模块名前缀，一眼看出是谁打的。

bind 的第一个参数设定 this（这里保持为 console），之后的参数会被固定在最前面 —— 这叫偏函数应用（partial application）。 用 bind 而不是包一层 (...args) => console.log(...) 还有一个好处：控制台显示的源码位置是调用处，而不是包装函数内部，点击就能跳到真正打日志的那一行。

适合追踪循环次数、递归调用次数、事件处理函数触发了几次（比如排查「为什么这个监听器执行了两次」）。 不传参数时使用名为 default 的计数器；console.countReset('user') 可以归零。 和其他 console 方法一样，它是调试工具，不应该用来统计生产环境的使用数据。

💡 上线前清理 console

大量 console.log 留在生产环境中，既泄露内部信息，也有轻微的性能开销（被打印的对象无法被垃圾回收）。 常见做法是在构建时自动移除，比如 esbuild / Vite 的 drop: ['console', 'debugger']，或 Terser 的 drop_console 选项； 也可以只保留 warn 和 error。

小结

  • %c 添加样式；info / warn / error / debug 区分级别，控制台可按级别过滤。
  • console.log.bind(console, 前缀…) 生成带前缀的日志函数，并保留正确的源码位置。
  • table 看数组和对象，group / groupCollapsed / groupEnd 组织层级，time / timeLog / timeEnd 计时，count 计数。
  • console.log({ 变量 }) 同时打印名字和值；注意对象是活引用，需要快照时先复制。
  • trace 打印调用栈；assert 失败只打印不中断；dir 以对象形式查看。
