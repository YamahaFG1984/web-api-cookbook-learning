第 6 章

观察 DOM 元素

「元素滚动到屏幕里了吗？」「元素的尺寸变了吗？」「元素的子节点被改了吗？」 以前回答这些问题要监听滚动事件、开定时器反复测量，既麻烦又耗性能。 现在浏览器提供了三个观察者：IntersectionObserver、ResizeObserver、MutationObserver， 你只需要说「我关心什么」，变化发生时浏览器会通知你。

本章目标

  • 掌握三种观察者共同的使用模式：创建 → observe → 回调收到 entries → 断开
  • 用 IntersectionObserver 实现图片懒加载、视频自动暂停、滚动入场动画、无限滚动
  • 用 MutationObserver 监听子元素变化并平滑过渡高度
  • 用 ResizeObserver 根据元素尺寸调整内容
  • 了解哪些场景今天已经可以用纯 HTML / CSS 解决（loading="lazy"、容器查询、滚动驱动动画）

三种观察者，一个套路

观察者关心什么entry 里有什么典型用途
IntersectionObserver元素与视口（或某个滚动容器）是否相交、相交多少isIntersecting、intersectionRatio、target懒加载、曝光统计、无限滚动
ResizeObserver元素尺寸变化contentRect、contentBoxSize、borderBoxSize自适应组件、图表重绘
MutationObserver子节点、属性、文本内容的变化type、addedNodes、removedNodes、attributeName响应第三方代码的 DOM 修改

6.3视频滚出屏幕时自动暂停

页面上有一个正在播放的视频，用户把它滚出屏幕时自动暂停，滚回来时继续播放。

⚠ 自动播放策略

浏览器对自动播放很严格：有声视频在用户与页面交互（点击、按键）之前，调用 play() 会被拒绝（Promise 以 NotAllowedError 拒绝）。 静音视频（muted 属性）通常允许自动播放。

无障碍角度看，页面一打开就自动播放视频也不好：可能引发前庭障碍用户不适，声音还会干扰屏幕阅读器。 实践中，这个方案应该只用于「用户已经主动点了播放」之后的便利功能 —— 比如记录一个 userStarted 标志，只有为 true 时才自动恢复播放。

6.4内容变化时平滑过渡高度

一个元素的内容会动态变化，你希望它的高度能平滑地过渡，而不是突然跳变。

难点在于：CSS 不能从 height: auto 过渡到另一个 auto，必须是两个具体的像素值。 所以思路是：用 MutationObserver 监听子节点变化 → 测量新旧高度 → 在两个像素值之间过渡。

MutationObserver 的观察选项

observe(element, options) 的第二个参数决定观察哪些变化，至少要开启 childList、attributes、characterData 其中之一：

选项作用
childList: true子节点被添加或删除
attributes: true属性变化；配合 attributeFilter: ['class', 'hidden'] 只看指定属性，attributeOldValue: true 记录旧值
characterData: true文本节点内容变化；characterDataOldValue: true 记录旧值
subtree: true以上观察扩展到所有后代节点，而不仅是元素本身和直接子节点

回调里读取的是 entries[0].contentRect.width，也就是不含内边距和边框的「内容区」宽度。

⚠ 小心无限循环

如果回调里的修改又改变了元素尺寸（比如修改后的文字把元素撑大了），就会再次触发回调…… 浏览器会在同一帧内中止这个循环，并在控制台报 「ResizeObserver loop completed with undelivered notifications」。 避免在回调里改变被观察元素本身的尺寸；确实需要时，把修改放进 requestAnimationFrame 推迟到下一帧。

再用一个观察者观察所有需要动画的图片，露出 25% 时把 opacity 改为 1：

  • threshold: 0.25 让回调在元素露出 25% 时才触发，确保用户能看到动画。默认值 0 时，露出 1 像素就触发，动画很可能在屏幕外就播完了。
  • 检查 isIntersecting 很有必要：开始观察时回调会立即执行一次，报告每个元素的初始状态，屏幕外的元素也会出现在 entries 里（isIntersecting 为 false）。
  • 一个观察者观察多个元素，比每个元素各建一个观察者高效得多。

用户滚到列表底部时自动加载更多数据，不需要点「加载更多」按钮。

在列表末尾放一个「哨兵」元素（sentinel），观察它。哨兵一进入视口，说明用户快滚到底了，就加载下一页：

哨兵可以是一个转圈的加载图标：默认 threshold 为 0，哨兵刚露出一个像素时回调就触发了，等用户真正看到转圈时数据已经在加载， 所以这个加载图标是「真实」的。另外，列表为空时哨兵一开始就可见，于是第一页数据也会被自动加载。

⚠ 实战中要补上的两个细节
  1. 防止重复加载：请求还没回来时，哨兵可能再次触发（比如用户上下滚动）。用一个 loading 标志挡住。
  2. 加载完哨兵仍然可见：如果一页数据太少，追加后哨兵依然在视口里，但「相交状态」没有变化，观察者不会再次通知，列表就卡住了。 解决办法是加载完后 unobserve 再 observe 一次，强制重新报告当前状态。

小结

  • 三种观察者用法一致：new 时传回调，observe 指定目标，回调收到 entries 数组，用完 unobserve / disconnect。
  • IntersectionObserver：threshold 控制触发比例，rootMargin 扩大或缩小判定区域，root 指定滚动容器。
  • MutationObserver：用 childList / attributes / characterData / subtree 选择观察范围。
  • ResizeObserver：回调里不要改变被观察元素的尺寸，避免循环。
  • 能用 HTML / CSS 解决的先用它们：loading="lazy"、容器查询、Grid 高度过渡、滚动驱动动画；JS 观察者用于需要逻辑的场景。
