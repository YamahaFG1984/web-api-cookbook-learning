第 7 章

表单

表单是用户向你的应用「说话」的主要方式。浏览器其实已经内置了相当完整的表单能力： FormData 帮你收集数据，约束校验 API（Constraint Validation API）帮你检查数据。 很多时候，你并不需要引入一个表单校验库。

本章目标

  • 用 form.elements 读写字段，用 FormData 收集并提交数据
  • 把表单转换为 JSON 提交，正确处理同名的多选字段
  • 用 required、min/max/step、pattern、type 声明校验规则
  • 用 checkValidity、invalid 事件、setCustomValidity 打造自己的校验体验
  • 实现复选框组校验和异步（调用接口）校验，并用 :user-invalid 简化「何时显示错误」

两件利器：FormData 与约束校验

浏览器默认的校验提示（气泡）样式无法定制，往往和应用的设计格格不入。约束校验 API 让你读取浏览器的校验结果， 用自己的方式展示错误，还能加入自定义规则。核心成员：

checkValidity()
在表单或单个字段上调用。全部有效返回 true；否则返回 false，并在每个无效字段上触发 invalid 事件
reportValidity()
同上，但还会弹出浏览器自带的错误气泡
validity
每个字段上的 ValidityState 对象：valid 表示总体是否有效，其余标志说明「错在哪」
validationMessage
浏览器生成的错误提示文本（跟随用户的浏览器语言）
setCustomValidity(msg)
设置自定义错误；传空字符串表示清除

ⓘ 用 form.elements 按名字找字段

form.elements 是表单内所有控件的集合，可以用字段的 name（或 id）直接访问： form.elements.username、form.elements['user-name']。 比 document.querySelector 更精确，不会误拿到页面上其他表单的同名字段。

💡 也别忘了浏览器自带的记忆

给字段写上合适的 autocomplete 属性（如 autocomplete="username"、"email"、"current-password"）， 浏览器和密码管理器就能自动填充，通常比自己存 localStorage 体验更好，也更安全。

内置校验规则（7.4 – 7.6）

下面三个配方都是在 HTML 上加属性，不写一行 JS。它们一起讲更容易对比：

7.4必填字段：required

required 是布尔属性，不需要写值。字段为空时 validity.valueMissing 为 true。 注意它只判断「是否为空字符串」，不会去掉空格 —— 输入几个空格也算「有值」。

7.5数字范围：min / max / step

min 和 max 都是包含边界的。小于最小值时 rangeUnderflow 为 true，大于最大值时 rangeOverflow 为 true。 数字框的上下箭头不会越界，但用户依然可以直接键入任何数字，所以校验仍然必要。

step 限制「步长」：min="0" max="4" step="2" 时只有 0、2、4 合法，输入 3 会触发 stepMismatch。

7.6正则模式：pattern

值不匹配正则时 patternMismatch 为 true。pattern 会自动匹配整个值（相当于自动加了 ^(?: 和 )$）， 并且只在字段非空时才检查（空值交给 required 管）。 校验邮箱和网址的正则很难写对，直接用 type="email" 和 type="url"，浏览器会替你检查格式（typeMismatch）。

⚠ 现代浏览器用 v 标志编译 pattern

自 2023 年起，主流浏览器用正则的 v（unicodeSets）标志来编译 pattern，规则比以前更严格。 例如 pattern="[\w-]+" 在 v 模式下是语法错误，浏览器会静默忽略整个 pattern，校验等于没写！ 字符类里的 -、(、)、[、{、/、| 等需要转义：写成 [\w\-]+。 写完后可以在控制台用 new RegExp('^(?:' + p + ')$', 'v') 测试一下。

7.8自定义校验逻辑

有些规则 HTML 属性表达不了，比如「两次输入的密码必须一致」。

在调用 checkValidity 之前执行自己的检查，不通过就用 setCustomValidity(错误信息) 把字段标记为无效； 通过时务必 setCustomValidity('') 清除，否则字段会一直无效。

设置了非空的自定义信息后，字段的 validity.customError 为 true，checkValidity 会像对待其他错误一样触发它的 invalid 事件， 所以 7.7 节的错误显示逻辑可以原样复用。如果你用的是浏览器自带的错误气泡，设置完还要调用 reportValidity() 才会显示。

小结

  • form.elements.名字 读写单个字段；new FormData(form) 是一次性快照，可以直接作为 fetch 的 body。
  • 转 JSON 用 Object.fromEntries，多选字段用 getAll；没勾选的复选框不会出现在 FormData 中。
  • required、min/max/step、minlength/maxlength、pattern、type 声明规则，validity 报告错在哪。
  • novalidate + invalid 事件 + validationMessage 实现自定义错误展示；:user-invalid 负责「何时显示」。
  • setCustomValidity 接入任意自定义规则（包括异步规则），记得在通过时传空字符串清除。
