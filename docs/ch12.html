Web Components

React、Vue 这些框架都有「组件」的概念。其实浏览器本身也有：Web Components 让你定义全新的 HTML 标签， 比如 <profile-card>，它自带结构、样式和行为，可以在任何页面、任何框架里使用，而且不依赖任何库。

本章目标

  • 理解 Web Components 的三大支柱：自定义元素、Shadow DOM、模板与插槽
  • 掌握生命周期回调与 observedAttributes
  • 用插槽（slot）把外部内容「投影」进组件
  • 从组件内部派发自定义事件，并让它穿过 Shadow DOM 边界
  • 完成日期、反馈、名片、懒加载图片、折叠面板、按钮六个组件，了解声明式 Shadow DOM、表单关联等现代能力

⚠ 三条硬性规定
  • 名字必须包含连字符（my-component，不能是 mycomponent），这样永远不会与未来的原生标签冲突。
  • 必须写闭合标签：<my-component></my-component>，不能自闭合。
  • 同一个名字只能 define 一次，重复注册会抛异常。不确定时先检查：if (!customElements.get('my-component')) { … }。

Shadow DOM 与 Light DOM

Shadow DOM 是挂在元素上的一棵独立 DOM 子树，与页面的主 DOM 隔离。最大的好处是样式作用域： Shadow DOM 内定义的样式只作用于内部元素；页面的全局样式也作用不到里面。这种隔离是双向的。

  • open / closed：attachShadow({ mode: 'open' }) 时外部可以通过 element.shadowRoot 访问内部；closed 时 shadowRoot 为 null。一般用 open 即可，closed 并不能真正防止别人访问。
  • Light DOM：组件的普通子元素（包括被投影到插槽中的内容）。它们不在 Shadow DOM 里，所以全局样式对它们有效。
  • Shadow DOM 是可选的。不用它也可以写自定义元素（直接操作 this 的子元素），只是没有样式隔离。

🔑 两个需要补上的细节
  • 无障碍：按钮应该带上 aria-expanded="true/false"，让屏幕阅读器知道面板的状态。
  • 重复监听：connectedCallback 在元素每次被插入 DOM 时都会调用。如果元素被移动过，按钮上就会有两个点击监听，一次点击切换两次、看起来「没反应」。 事件监听最好放在 constructor 里（Shadow DOM 内的元素那时已经存在），或者在 disconnectedCallback 中移除。

另外别忘了，第 13 章会介绍原生的 <details> 元素 —— 它开箱即用地实现了这一切。

小结

  • 继承 HTMLElement 写类，customElements.define('带-连字符', 类) 注册。
  • 生命周期：constructor（初始化、attachShadow）→ connectedCallback（可能多次）→ disconnectedCallback（清理）；attributeChangedCallback 只对 observedAttributes 生效。
  • <template> 提供结构，<slot> 投影外部内容（命名插槽用 slot="名字" 匹配）。
  • Shadow DOM 双向隔离样式；:host 选中宿主；CSS 变量、继承属性、::part() 可以穿过边界。
  • 自定义事件需要 bubbles（从 shadowRoot 派发时还需 composed）才能被外部收到；数据放在 detail。
  • 用 :not(:defined) 防闪烁；需要参与表单时使用 formAssociated + ElementInternals。
