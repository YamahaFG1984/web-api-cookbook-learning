事件对象与三个阶段

当用户点击页面上的一个按钮时，浏览器会创建一个事件对象（这里是 PointerEvent），然后让它沿着 DOM 树走一个来回： 先从 window 一路向下到被点击的元素，再从那里一路向上回到 window。沿途每个节点上的监听器都有机会处理它。

事件对象上最常用的几个属性：

event.type
事件名，如 'click'
event.target
事件真正发生在哪个元素上（被点击的最内层元素）
event.currentTarget
当前正在执行的这个监听器挂在哪个元素上。冒泡过程中 target 不变，currentTarget 一路变化
event.eventPhase
当前处于哪个阶段
event.bubbles
这个事件会不会冒泡。大多数会，但 focus、blur、mouseenter、load 等不会
event.isTrusted
是用户真实操作产生的（true），还是代码 dispatchEvent 出来的（false）

💡 什么时候会用到捕获阶段？

日常开发中 99% 的监听器都在冒泡阶段。捕获阶段适合「必须抢在所有人之前处理」的场景，比如全局的埋点统计、 在任何子组件处理之前拦截某些点击。另外，focus / blur 不冒泡，但可以在父元素上用捕获阶段监听到（或者改用会冒泡的 focusin / focusout）。

⚠ 慎用 stopPropagation

阻止传播会让上层的代码「失聪」：比如「点击页面空白处关闭菜单」的逻辑、分析工具的全局点击统计、事件委托，都依赖冒泡。 很多诡异的「点了没反应」bug 都来自某处随手写的 stopPropagation()。 多数时候，你真正想要的其实是在上层判断 event.target，而不是切断传播。

20.3事件委托

一个列表有成百上千项，而且会动态增删。给每一项单独绑定监听器既浪费内存，又要在新增时记得补绑定。

既然事件会冒泡，就只在父元素上监听一次，再根据 event.target 判断点的是哪一项。这叫事件委托（event delegation），第 12 章的反馈组件也用过：

🔑 为什么用 closest 而不是直接比较 event.target？

event.target 是被点中的最内层元素。如果按钮里有 <span> 或图标，点到它们时 target 就不是按钮了。 element.closest(选择器) 从自身开始向上找第一个匹配的祖先，完美解决这个问题。 加上 list.contains(...) 判断，可以防止匹配到列表外面的同名元素。

你要做一个画板：电脑上用鼠标画，手机上用手指画，平板上用手写笔画，还想利用笔的压感。

过去要分别写 mousedown/mousemove/mouseup 和 touchstart/touchmove/touchend 两套代码，逻辑还不一样（触摸事件有多个触点）。 Pointer Events 把它们统一成一套：Baseline 广泛可用

⚠ 别忘了 touch-action

在触屏设备上，浏览器会把手指拖动当作「滚动页面」，并触发 pointercancel，你的画板就画不出线。 CSS 的 touch-action: none 告诉浏览器把触摸交给你处理。只想禁止横向拖动时，可以写 touch-action: pan-y（仍允许竖向滚动）。

20.5键盘事件

实现快捷键（如 Ctrl+S 保存）、在输入框里按回车发送消息，而且要兼容中文输入法。

key 与 code

属性含义按 A 键（英文）按 A 键 + Shift德语键盘上按 Z 所在位置
event.key这次按键「产生了什么字符 / 功能」'a''A''y'
event.code按下的是键盘上「哪个物理位置」的键'KeyA''KeyA''KeyZ'

判断「用户想输入什么」用 key（如 'Enter'、'Escape'、'ArrowUp'）； 游戏里的 WASD 方向键这类「按位置」的需求才用 code。旧的 keyCode、which 已经废弃，不要再用。 修饰键通过 event.ctrlKey、metaKey（Mac 的 ⌘）、shiftKey、altKey 判断。

中文输入法的陷阱：isComposing

用拼音输入法打字时，敲下的字母先进入「组字」状态（候选框），这时按回车通常是确认候选词，而不是发送消息。 如果直接监听 Enter，用户选词时消息就被误发出去了 —— 这是中文用户最常遇到的网页 bug 之一。

试一试：键盘事件查看器（切换到中文输入法打几个字，再按回车）
💡 监听文字变化，用 input 而不是 keydown

想在「输入框内容变化」时做事（实时搜索、字数统计），应该监听 input 事件：粘贴、拖放、语音输入、输入法上屏都会触发它， 而 keydown 只关心按键。在内容改变之前拦截，可以用 beforeinput，它的 event.inputType 告诉你是插入、删除还是粘贴。

20.7监听选项与移除监听

监听器只需要执行一次、需要一次性移除一批监听器，或者滚动时监听 touch 事件导致页面卡顿。

选项作用典型场景
{ once: true }执行一次后自动移除等待一次 transitionend、第 13 章的 close 事件
{ capture: true }在捕获阶段执行20.1 节
{ passive: true }承诺不会调用 preventDefault()touchmove、wheel：浏览器不必等你的代码执行完再滚动，滚动更流畅
{ signal }AbortController.abort() 时自动移除组件销毁时一次性清理所有监听（第 1 章）
⚠ 匿名函数无法移除

另外，removeEventListener 的 capture 选项必须与添加时一致，否则同样移除不掉。 忘记移除监听器，是单页应用内存泄漏的主要原因之一（比如组件销毁了，window 上的 resize 监听还引用着它）。

ⓘ passive 的默认值

为了让滚动更流畅，主流浏览器会把注册在 window、document、body 上的 touchstart、touchmove、wheel 监听器默认视为 passive。 所以在这些监听器里调用 preventDefault() 会被忽略（并在控制台警告）。确实需要阻止滚动时，显式传入 { passive: false }， 或者更好的办法：用 20.4 节的 CSS touch-action。

小结

  • 事件传播分三个阶段：捕获（外 → 内）、目标、冒泡（内 → 外）；默认监听器在冒泡阶段执行。
  • target 是事件发生的元素，currentTarget 是监听器所在的元素。
  • preventDefault 取消浏览器的默认动作；stopPropagation 阻止传播 —— 两者无关，后者要慎用。
  • 事件委托：在父元素上监听一次，用 event.target.closest() 找到真正的目标，天然支持动态元素。
  • Pointer Events 统一鼠标 / 触摸 / 笔；配合 setPointerCapture 和 CSS touch-action。
  • 键盘：用 key 判断字符、code 判断物理位置；处理 Enter 前先检查 isComposing。
  • 继承 EventTarget 实现发布订阅；用 once、passive、signal 管理监听器的生命周期。
