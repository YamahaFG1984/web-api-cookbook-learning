第 13 章

UI 元素

对话框、折叠面板、弹出层、工具提示、系统通知 —— 这些界面元素过去都要靠第三方库或自己手写。 现在浏览器原生提供了 <dialog>、<details>、Popover API 和 Notification API， 它们自带键盘操作、焦点管理和无障碍语义，比大多数手写实现都更可靠。

本章目标

  • 用 <dialog> 做提示框和确认框，理解 returnValue、cancel、close 事件
  • 把确认框封装成返回 Promise 的 Web Component
  • 用 <details> 做折叠面板（含互斥的「手风琴」）
  • 用 Popover API 做弹出层和工具提示，并把它定位到触发按钮旁边（JS 方案与 CSS 锚点定位）
  • 用 Notification API 发送系统通知

13.5显示弹出层（Popover）

点击按钮弹出一块内容，但用户仍然可以操作页面的其他部分。

零 JS：给元素加 popover 属性（它就会默认隐藏），给按钮加 popovertarget="元素 id"，点击按钮就能开关。 与对话框不同：没有遮罩，不阻挡页面，点击弹出层外部会自动关闭（称为 light dismiss），按 Esc 也会关闭。 同一时刻只会有一个 auto 弹出层是打开的（除非它们是嵌套关系），打开新的会关闭旧的。

13.7把弹出层定位到元素旁边

弹出层默认出现在屏幕正中，你希望它出现在触发按钮的正下方。

你可能会疑惑：position: absolute 通常相对于最近的已定位祖先元素，这里为什么是相对整个文档？ 因为打开的弹出层被放进了图 13-1 中的顶层，无论它在 DOM 的哪里，都不再受祖先元素影响。 （原书正文说「设置 position: fixed」，但示例代码用的是 absolute：fixed 相对视口、不随页面滚动，absolute 则需要加上 scrollY。）

这个方案有两个局限：按钮靠近页面底部时，下方可能放不下弹出层（需要判断后改到上方）；窗口大小变化时位置不会自动更新（需要 resize 事件或 ResizeObserver）。

13.9系统通知

当应用里发生了某件事（新消息、任务完成），用操作系统的原生通知提醒用户。

  • 只能在安全上下文中使用：HTTPS 页面或 localhost。
  • 通知对象还有 show、close、click、error 事件；未授权时创建通知会触发 error。
  • 请在用户操作之后再请求权限（比如点击「开启提醒」按钮）。页面一打开就弹授权框，大多数用户会直接拒绝，Firefox 和 Safari 甚至会忽略非用户手势触发的请求。
ⓘ 通知 vs 推送通知

本节的通知只能在页面打开期间由页面代码创建。想在用户没打开网站时也能收到提醒（像手机 App 那样），需要 推送通知：Service Worker + Push API + 服务器端的推送服务。iOS / iPadOS 上的 Safari 只允许「已添加到主屏幕」的 Web 应用使用通知。

小结

  • <dialog>：showModal() 模态 / show() 非模态；close(value) 设置 returnValue；Esc 触发 cancel 再触发 close。
  • 关闭的对话框仍在 DOM 中，returnValue 会残留，需要在 cancel 中或打开前重置。
  • 把「多个事件」封装成返回 Promise 的方法，调用方只需 await。
  • <details> + <summary> 是零 JS 的折叠面板；相同 name 组成手风琴。
  • Popover：popover + popovertarget 零 JS；manual 模式用 showPopover / hidePopover / togglePopover。打开的弹出层位于顶层。
  • 定位：JS 用 getBoundingClientRect() + scrollY；新浏览器可用 CSS 锚点定位。
  • 通知：安全上下文、用户操作后请求权限、granted 后才能 new Notification()。
