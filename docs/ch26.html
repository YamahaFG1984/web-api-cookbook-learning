Web Audio API

<audio> 元素能播放一个音频文件，但仅此而已。Web Audio API 则是一套完整的「音频工作站」： 你可以凭空合成声音、精确到毫秒地安排节奏、实时加上混响和滤波、分析频谱画出可视化效果。 网页游戏的音效、在线合成器、音乐教学应用、语音处理，都靠它实现。

本章目标

  • 理解 AudioContext 与「音频节点图」的工作方式，以及自动播放限制
  • 用振荡器和增益节点合成声音，用包络消除爆音
  • 用音频时钟精确调度，做一个节拍器 / 鼓机
  • 播放音频文件、接入麦克风，加上滤波、声像等效果
  • 用 AnalyserNode 配合第 25 章的 Canvas 画出波形和频谱
ⓘ 本章的演示会发出声音

26.1合成声音：振荡器

你要给游戏加一些音效（按钮提示音、得分音），但不想为每个音效都准备一个音频文件。

声音就是空气的振动。振荡器按指定的频率（每秒振动多少次，单位 Hz）和波形产生信号。 频率决定音高，波形决定音色：

🔑 音源节点是「一次性」的

OscillatorNode 和 AudioBufferSourceNode 只能 start() 一次，停止后就不能再用了。 每次要发声都新建一个，这很便宜，不必担心性能；它们停止后，如果没有别的引用，会被自动回收。

26.2用包络消除爆音

用上面的 beep 连续播放，每个音开始和结束时都有「啪」的一声杂音。

原因是波形被突然截断：振荡器在任意位置开始或停止，扬声器的振膜瞬间跳变，就会产生一声「咔哒」。 解决办法是让音量平滑地升起和落下，这条随时间变化的音量曲线叫包络（envelope）：

音量（gain.gain）、频率（osc.frequency）这些可以随时间变化的参数都是 AudioParam， 它们可以预先安排好在音频时间线上的变化，由音频线程精确执行：

AudioParam 方法效果
setValueAtTime(v, t)在时刻 t 突变为 v
linearRampToValueAtTime(v, t)从上一个值线性过渡，在 t 时到达 v
exponentialRampToValueAtTime(v, t)指数过渡（适合音量和频率，符合人耳感知）；v 不能是 0
setTargetAtTime(v, t, 时间常数)从 t 开始向 v 渐近（常用于「松开按键时淡出」）
cancelScheduledValues(t)取消 t 之后安排好的变化

26.3精确调度：节拍器与鼓机

你想做一个节拍器或鼓机，但用 setInterval 播放的节奏总是忽快忽慢。

JS 的定时器跑在主线程上，主线程一忙（第 21 章），回调就会迟到几毫秒到几十毫秒，人耳对节奏的偏差非常敏感。 而 ctx.currentTime 是运行在独立音频线程上的音频时钟，osc.start(t) 可以精确到采样级别。 正确的做法是「两个时钟配合」：用不精确的 JS 定时器频繁地「往前看」，把接下来一小段时间内的音符，提前交给精确的音频时钟去安排：

✨ 自定义处理：AudioWorklet

内置节点满足不了需求时（自己的合成算法、音高检测、降噪），可以用 AudioWorklet 编写运行在音频线程上的 JS（或 WebAssembly）处理器， 每次处理 128 个采样，延迟极低。Baseline 广泛可用 渲染不需要实时播放的音频（比如导出一段混音）时，可以用 OfflineAudioContext，它会以最快速度「离线」算完，再用第 18 章的方法导出。

小结

  • 一个页面一个 AudioContext；它一开始是 suspended，要在用户交互中 resume()。
  • 音源 → 处理节点 → destination，用 connect() 连成图；音源节点只能 start() 一次，每次新建。
  • 振荡器合成声音，频率决定音高、波形决定音色；用 AudioParam 的自动化方法做包络，避免爆音。
  • 需要准确节奏时，用 ctx.currentTime 提前安排（「向前看」调度），而不是在定时器回调里直接播放。
  • 短音效用 decodeAudioData + AudioBufferSourceNode，长音乐接 <audio>，麦克风接 MediaStreamAudioSourceNode。
  • AnalyserNode 提供波形与频谱数据，配合 Canvas 做可视化；自定义算法用 AudioWorklet。
